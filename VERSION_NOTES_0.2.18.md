# Version 0.2.18 - FTS rowid keying (F-1, ADR-003 option a) and NFC normalization (F-2)

STATUS: written, NOT compiled, NOT run. Everything below is UNCONFIRMED until the next CI run
(normal workflow) and the next emulator run (instrumented workflow) are green.

Evidence that motivated the change (emulator, API 34, v0.2.17):
- 20,000 rows: edit 5.12 ms, delete 5.51 ms per row.
- 300,000 rows: edit 127.7 ms, delete 117.7 ms per row; FTS delete by question_id 105.2 ms vs by rowid 0.117 ms.

F-1 changes
- type_cq_questions and chapter_cq_questions: new column `fts_id INTEGER NOT NULL UNIQUE`
  (app-assigned; used as the FTS5 rowid).
- FTS tables no longer store question_id: fts5(question_text, short_answer, tokenize=...).
- FTS triggers: insert uses rowid=NEW.fts_id; update fires on fts_id/question_text/short_answer and
  deletes/inserts by rowid; delete removes by rowid=OLD.fts_id. Trigger count is unchanged (17 + 46).
- Search joins use `JOIN <questions> q ON q.fts_id = f.rowid`.
- New FtsIdAllocator (read MAX(fts_id) once per write transaction, then next()). fts_id is internal:
  never exported to backups; restore/import always allocate new values.
- Room entities: new `ftsId` field and unique index on fts_id. Schema 1.json is regenerated by KSP in CI
  and must be committed from the CI report (database version stays 1; nothing is released).
- Offline prototype (Python sqlite3 3.45, 100,000 rows, desktop CPU): edit 0.040 ms, delete 0.044 ms per row,
  FTS row count equals question count, missing and duplicate fts_id are rejected. Not a device result.

F-2 changes
- New BanglaText.normalize() = NFC. U+09DF, U+09DC and U+09DD are composition exclusions, so NFC maps them
  to base letter + nukta; no separate folding table is needed. Apply on write and on every search query.
- RoomRuntimeTest.banglaNormalizationReport (information only) replaced by an asserting test.
- New JVM tests: BanglaTextTest (4 tests).

Test changes
- RoomRuntimeTest: +2 new tests (fts_id required and unique; join by fts_id follows edit and delete) and the normalization report test replaced by an asserting one.
- ScaleBenchmarkTest: explicit fts_id via the allocator; searches use rowid/fts_id join; experiment replaced by a
  consistency assertion (question rows == FTS rows).
- Expected counts if all passes: unit tests 7 + 4 = 11; emulator tests 9 + 2 = 11 (10 runtime tests + the benchmark; the normalization report test is replaced, not added).
