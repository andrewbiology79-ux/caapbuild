CATEGORY FOLDER SYNC UPDATE — IMPLEMENTATION NOTES

উদ্দেশ্য
Type CQ ও Chapter CQ-এর বিদ্যমান Question_Bank ফোল্ডার সিঙ্ক অক্ষত রেখে Category ও তার Paper-গুলোকে আলাদা ফোল্ডারে সংরক্ষণ এবং Sync করা।

নতুন ফোল্ডার কাঠামো
Download/QB Collection/
  Question_Bank/
    Type_CQ/       (আগের মতো)
    Chapter_CQ/    (আগের মতো)
  Category/
    <Category Name>/
      .folder.json
      <Paper Name>.json

Paper JSON-এ paper ID, নাম, title, questionIds, paper-specific edits, marks/time/order-সহ বিদ্যমান Paper metadata রাখা হয়। প্রশ্নের আসল কনটেন্ট ও ছবি Question_Bank-এর Type_CQ/Chapter_CQ data.json এবং media/ ফোল্ডারেই থাকে; Paper JSON সেগুলোর question ID reference ধরে। ফলে একই প্রশ্নের duplicate কপি তৈরি হয় না।

যা যুক্ত করা হয়েছে
1. নতুন categorySync.ts: Category/Paper-এর folder write ও folder scan পরিচালনা করে।
2. Category এবং Paper table-এ Dexie hooks: অ্যাপে পরিবর্তন হলে debounce করে Category ফোল্ডারে লেখা হয়।
3. Folder sync চালু করার সময় বিদ্যমান Category/Paper-গুলোও প্রথমবার ফোল্ডারে লেখা হয়।
4. ম্যানুয়াল Folder Sync-এ Category ফোল্ডার scan হয়; নতুন Category/Paper এবং পরিবর্তিত Paper অ্যাপে আনা হয়।
5. Category ID .folder.json-এ এবং Paper ID JSON ফাইলে থাকে; তাই নাম বদলালেও ID-ভিত্তিক matching করা যায়।
6. অপ্রয়োজনীয়/অচেনা ফাইল স্বয়ংক্রিয়ভাবে মোছা হয় না।
7. অ্যাপ থেকে Category মুছলে তার ফোল্ডার Category/unnecessary/ এর নিচে সরানো হয়, যাতে পরের Sync-এ সেটি আবার Category হিসেবে ফিরে না আসে।
8. অ্যাপ থেকে Paper মুছলে কেবল Sync state-এ আগে থেকে চিহ্নিত ওই Paper ফাইলটি মোছা হয়; অচেনা ফাইল স্পর্শ করা হয় না।
9. একই content থাকলে ফাইল পুনরায় লেখা হয় না; নিরাপদ write helper ব্যবহার করা হয়েছে।
10. Category sync-কে বিদ্যমান sync lock-এর সঙ্গে যুক্ত করা হয়েছে, যাতে একই সময়ে একাধিক folder operation না চলে।

সিঙ্কের আচরণ ও নিরাপত্তা
- App → Folder: Category create/rename/delete এবং Paper create/update/delete প্রতিফলিত হয়।
- Folder → App: নতুন Category/Paper, Category folder rename, Paper JSON edit অ্যাপে পড়ে আসে।
- Folder থেকে কোনো Category/Paper ফাইল মুছে দিলে এই সংস্করণে অ্যাপের ডেটা স্বয়ংক্রিয়ভাবে delete করা হয় না। এটি ইচ্ছাকৃত data-loss protection; ফলে ফোল্ডার থেকে মুছে ফেলা item অ্যাপে থেকে যেতে পারে এবং পরবর্তী App → Folder write-এ পুনরায় লেখা হতে পারে।
- Folder sync-এর বর্তমান Preview dialog-এ Category-র আলাদা line-item preview এখনো যোগ করা হয়নি; Category ফলাফল Sync report-এর added/updated/warnings সংখ্যার সঙ্গে যুক্ত হয়।
- Category paper JSON-এ question ID reference থাকে; প্রশ্ন ও image binary আলাদা করে Category ফোল্ডারে duplicate করা হয় না। সেগুলো Question_Bank-এর বিদ্যমান Type CQ/Chapter CQ sync-এ থাকে।

ব্যবহার করার ধাপ
1. ZIP extract করে প্রজেক্টের বর্তমান source-এর সঙ্গে আপডেটেড source ব্যবহার করুন।
2. npm ci চালান।
3. npm run lint এবং npm test চালান।
4. Android build তৈরি করে একটি test device-এ ইনস্টল করুন।
5. অ্যাপের Folder Sync চালু করুন। চালু করার আগে অ্যাপের auto backup সম্পন্ন হতে দিন।
6. ফোনে Download/QB Collection/Category/ ফোল্ডারে Category এবং তার Paper JSON তৈরি হয়েছে কি না দেখুন।
7. অ্যাপে একটি test Category ও Paper তৈরি/rename/update/delete করে ফোল্ডার মিলিয়ে দেখুন।
8. একটি test Paper JSON-এ নিরাপদ metadata পরিবর্তন করে ম্যানুয়াল Folder Sync দিন; অ্যাপে পরিবর্তন এসেছে কি না যাচাই করুন।
9. Type CQ ও Chapter CQ-এর আগের folder sync আলাদাভাবে পরীক্ষা করুন।

যাচাইয়ের অবস্থা
- সংশোধিত তিনটি TypeScript ফাইলের syntax transpile check সফল হয়েছে।
- পূর্ণ TypeScript lint/build/test এই পরিবেশে চালানো যায়নি: npm ci dependency install timeout হয়েছে এবং vite/client type package অনুপস্থিত ছিল। তাই ZIP-টিকে production-verified build বলা হচ্ছে না। Android device-এ ব্যবহার করার আগে উপরোক্ত lint/build ও sync test চালানো আবশ্যক।
