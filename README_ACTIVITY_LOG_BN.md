# অ্যাক্টিভিটি লগ (ডায়াগনস্টিক)

অ্যাপে আপনি কোথায় ট্যাপ করেছেন, কোন স্ক্রিনে কী করেছেন এবং সেভে কী হয়েছে — সব `activity_log.txt` ফাইলে সময়সহ লেখা হয়।

## ফাইল কোথায়
- অ্যাপের ভেতরে: প্রোফাইল ট্যাব → "অ্যাক্টিভিটি লগ" কার্ড → **লগ কপি করুন** (ক্লিপবোর্ডে যায়, শেষ ১৫০,০০০ অক্ষর)
- ফোনের ফাইল ম্যানেজারে: `Android/data/com.questionbank.app/files/activity_log.txt`
- ফাইল ১.৫ MB ছাড়ালে `activity_log_old.txt` নামে সরে যায়, নতুন ফাইল শুরু হয়।

## লাইনের ধরন
| ট্যাগ | কী লেখা হয় |
|---|---|
| TOUCH | ট্যাপ / লং-প্রেস / সোয়াইপ, স্ক্রিনের x,y (px ও dp), শতাংশ ও অঞ্চল (top-left ইত্যাদি) |
| NAVIGATE | স্ক্রিন বদল ও তার আর্গুমেন্ট (topicId, groupKey ...) |
| BACK | Back বাটন চাপা |
| TYPED | কোন ঘরে লিখেছেন — অক্ষরসংখ্যা ও প্রথম ৪০ অক্ষর (থামলে একটি লাইন) |
| ACTION | সেভ (✓), Undo/Redo, Minimum/Full Editor বদল, ক্যাটাগরি বাছাই, প্রশ্ন মোছা, সমাধানের ছবি/অংশ বদল |
| SAVE-DATA | সেভের সময় ডাটাবেজে পাঠানো সমাধান-অংশের (part_id সহ) তালিকা |
| DB-WRITE | রিপোজিটরি থেকে ডাটাবেজে লেখার ঠিক আগের অংশ-তালিকা |
| SAVE-RESULT | সেভের ফলাফল (Saved / Updated / Failed ...) |
| DB-FAIL | ব্যর্থ হলে exception ও সম্পূর্ণ stack trace |
| DB-FIX | সংঘাতের আইডি পেলে অ্যাপ নিজে নতুন আইডি দিয়ে সেভ সম্পন্ন করে, এই লাইন তার প্রমাণ |
| DB-DIAG | UNIQUE ব্যর্থতায় প্রতিটি part_id-র বর্তমান মালিক প্রশ্ন; সংঘাত হলে `<== COLLISION` |
| LIFECYCLE | অ্যাপ খোলা, ব্যাকগ্রাউন্ডে যাওয়া, ফিরে আসা, বন্ধ হওয়া |
| CRASH | অ্যাপ ক্র্যাশ করলে stack trace |

## সীমাবদ্ধতা
- ট্যাপে বাটনের নাম নয়, অবস্থান (x,y) লেখা হয়। নাম পেতে ওপরের ACTION লাইন দেখুন।
- লেখার পূর্ণ বিষয়বস্তু নয়, শুধু দৈর্ঘ্য ও প্রথম ৪০ অক্ষর রাখা হয়।
- এটি ডাটাবেজ পড়ে/বদলে না (কেবল ব্যর্থতার পর part_id-র মালিক খুঁজতে একটি SELECT চলে)।

## Type CQ Concept ও কার্ড অ্যাকশন
- Concept save ব্যর্থ হলে `CONCEPT-WRITE` Activity Log-এ কারণ ও stack trace লেখা হয়।
- Type CQ card category পরিবর্তন, clipboard, card deletion এবং move-এর ফল UI-তে status message হিসেবে দেখানো হয়; database transaction ব্যর্থ হলে সফলতার বার্তা দেখানো হয় না।
